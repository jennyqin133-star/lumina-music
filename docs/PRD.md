## 1. 产品概述

### 1.1 产品定位

**Lumina Music** 是一款以 AI Agent 为核心驱动的智能音乐创作与编辑平台。它不只是"输入文字出歌"的工具——而是让用户像拥有一个专业音乐制作团队：Agent 帮你分析歌曲、理解你的意图、生成结构完整的音乐、在像剪映一样简单的编辑室里精修、最后一键出封面。

### 1.2 产品愿景

让任何人都能用"对话 + 拖拽"的方式，完成从灵感到成品的音乐创作全流程，不需要乐理知识，不需要 DAW 学习成本。

### 1.3 目标用户

| 用户类型 | 特征 | 核心诉求 |
|---------|------|---------|
| 音乐爱好者 | 喜欢音乐但无专业背景 | 快速出歌、简单编辑 |
| 内容创作者 | 短视频博主/自媒体 | BGM 定制、快速出片 |
| DJ / 电子音乐玩家 | 喜欢混音、打碟 | DJ 效果、BPM 控制、实时混音 |
| 专业音乐人 | 有编曲基础 | 分轨导出、深度编辑、专业工作流对接 |
| AI 工具探索者 | 技术爱好者 | 尝鲜 AI 音乐能力、声音克隆 |

### 1.4 核心差异化

- **Agent 主动分析**：不是被动等提示词，而是你丢一首歌进去，Agent 主动拆解结构、风格、音色，然后跟你讨论下一步
- **编辑像剪映一样简单**：时间轴拖拽、一刀切割、自动桥接、人声分离一键搞定
- **DJ 模式内置**：不用切软件，编辑完直接进 DJ 模式搓碟
- **审核宽松**：产品层面对人声/人名 copy 不做预拦截，由用户自行负责合规
- **全流程打通**：分析 → 生成 → 编辑 → DJ → 封面 → 导出，一个平台闭环

## 3. 功能详述

### 3.1 AI Agent 音乐分析引擎

这是产品的"大脑"——用户通过对话式界面与 Agent 交互，Agent 理解意图并协调各模型完成分析。

#### 3.1.1 输入方式

| 输入类型 | 说明 | 支持的格式 |
|---------|------|-----------|
| 音频上传 | 用户上传一首歌曲 | MP3, WAV, FLAC, AAC, OGG, M4A |
| URL 导入 | 粘贴 YouTube/SoundCloud 等链接 | 平台支持的公开链接 |
| 麦克风录音 | 哼唱/弹奏录入 | 实时录音流 |
| 文字描述 | 用自然语言告诉 Agent 要做什么 | 中文/英文/中英混合 |

#### 3.1.2 Agent 分析能力

Agent 收到歌曲后，自动执行以下分析并在对话中呈现结果：

**结构分析**
- 识别并标注段落：[Intro] → [Verse 1] → [Pre-Chorus] → [Chorus] → [Verse 2] → [Bridge] → [Outro]
- 标注每段的时间戳（精确到秒）
- 识别段落的重复模式、变奏关系
- 分析歌曲总时长、各段落时长比例

**风格分析**
- 一级分类：流行/摇滚/电子/嘻哈/民谣/爵士/古典/R&B/国风/拉丁/...
- 二级细化：如"电子 → Future Bass / Synthwave / House / Techno / Dubstep"
- 情绪标签：欢快/忧伤/激昂/温柔/神秘/怀旧/性感/...
- 能量曲线：整首歌的能量变化趋势

**音色分析**
- 人声类型：男声/女声/童声/合唱，以及具体质感（明亮/沙哑/甜美/厚重/气声）
- 主奏乐器识别：钢琴/吉他/贝斯/鼓/合成器/弦乐/管乐/民族乐器
- 音色纹理：温暖/冷冽/复古/现代/原声/电子

**技术参数分析**
- BPM（每分钟节拍数）检测
- 调性（Key）检测
- 音阶/调式识别
- 动态范围

**歌词分析**（如歌曲含人声）
- 提取/转写歌词
- 分析韵脚、歌词结构
- 识别语言

#### 3.1.3 Agent 交互细节

Agent 分析完成后，不是干巴巴地输出报告，而是像音乐制作人一样跟用户对话：

```
Agent: "这首歌我分析完了——是个典型的 Pop-Rock，BPM 126，E大调。
       结构很标准：前奏4小节 → 主歌A(0:08) → 副歌(0:32) → 主歌B(1:02) → 副歌 → 桥段(2:10) → 副歌 → 尾奏。
       女声，偏亮的抒情嗓，副歌部分嗓音很有力量感。
       
       你刚才说想模仿 0:32-1:02 这段的音色——这段是副歌，人声饱满、合成器铺底、
       鼓点密集。我大概理解了，你是想用这个音色感觉去生成新歌，还是在这首歌基础上
       做 remix？"
```

**Agent 的主动提问策略**（仅在必要时触发）：

| 场景 | Agent 的提问 |
|------|-------------|
| 用户上传歌曲但未说明意图 | "你想让我分析这首歌的哪些方面？还是直接模仿它的某个部分？" |
| 风格模糊（模型置信度低） | "这首歌我听起来像是 indie pop 和 folk 的混合，你更偏向哪个方向？" |
| 音色模仿需求 | "你想模仿的是副歌的爆发力部分，还是主歌的轻柔部分？不同段落的音色处理不太一样。" |
| 准备生成前 | "歌词你想要英文、中文、还是中英混合？" |

#### 3.1.4 时间轴联动

分析结果中的所有段落标注均与音频时间轴可点击联动——用户点击 `[Chorus 0:32]`，编辑室的时间轴自动跳转到该位置。这在编辑环节非常关键。

### 3.2 AI 音乐生成

#### 3.2.1 生成模式

| 模式 | 说明 | 典型场景 |
|------|------|---------|
| **从零创作** | 纯文字描述，Agent 自动生成词曲编唱 | "一首关于夏天的中文流行歌，女声，轻快" |
| **基于参考生成** | 上传参考歌曲，模仿其结构/风格/音色 | "模仿刚才那首歌的副歌音色，但换成电子风格" |
| **片段生成** | 指定时间段或段落类型，只生成特定部分 | "帮我生成一段 8 小节的 intro，氛围感强的" |
| **Cover 翻唱** | 上传歌曲，保留旋律骨架，换风格/换歌词 | "把这首民谣改成重金属风格" |
| **延续创作** | 基于已有片段，续写后续段落 | "在这段 verse 后面接一个 pre-chorus" |
| **桥接生成** | 在两段音频之间生成平滑过渡 | "把这段 cut 掉后的前后两段桥接起来" |

#### 3.2.2 生成参数

用户在生成前可调节的参数：

| 参数 | 说明 | 范围/选项 |
|------|------|----------|
| 风格 | 音乐风格标签 | 预置标签 + 自定义 |
| 情绪 | 情感方向 | 欢快/忧伤/激昂/... |
| BPM | 每分钟节拍数 | 40-200（可自动检测） |
| 调性 | Key | 12 个调 + 自动检测 |
| 人声类型 | 性别/质感 | 男/女/童/合唱 + 音色描述 |
| 语言 | 歌词语言 | 中文 / 英文 / 中英混合（默认询问） |
| 时长 | 目标时长 | 30s / 1min / 2min / 4min / 8min |
| 结构 | 段落结构 | 预置模板 + 自定义 |
| 创意度 | 随机性控制 | 保守 / 平衡 / 大胆（类似 Suno weirdness） |
| 风格强度 | 对提示词的遵循程度 | 0-100% |

#### 3.2.3 模型调用策略

| 生成环节 | 使用模型 | 说明 |
|---------|---------|------|
| 音乐生成 | MiniMax Music 2.6 | 核心音乐生成，支持 Cover、结构控制、BPM/调性锁定 |
| 人声合成 | MiniMax Speech 2.8 HD | 高清人声，支持情感标签、40+语言、零样本克隆 |
| 歌词创作 | MiniMax M3 | 百万上下文，理解歌曲结构语境，生成押韵歌词 |
| 歌词润色 | MiniMax M2.7 / M3 | 根据用户反馈修改、润色 |
| 风格推理 | MiniMax M3 | Agent 对话、音乐知识推理 |

#### 3.2.4 歌词语言策略

> **规则**：如果用户在描述中没有明确说明歌词语言，Agent 必须询问"英文/中文/中英混合？"三个选项。用户选择后再生成。这是强制交互点，避免生成不符合预期的语言版本。

例外：用户输入歌词文本时，以输入文本的语言为准，不再询问。

### 3.3 音乐编辑工作室

这是产品的"操作中枢"——对标剪映的简洁操作体验 + 音频工作站的专业能力。

#### 3.3.1 界面布局

```
┌──────────────────────────────────────────────────┐
│  工具栏（切割/移动/删除/撤销/重做/缩放/吸附）  │
├──────┬───────────────────────────────────────────┤
│      │  时间轴（多轨横向展开）                   │
│ 轨道  │  ┌─────────────────────────────────────┐ │
│ 列表  │  │ 音轨1: 人声 (Vocal)                 │ │
│      │  │  ═══════════════════════════════     │ │
│      │  │ 音轨2: 伴奏 (Instrumental)           │ │
│      │  │  ═══════════════════════════════     │ │
│      │  │ 音轨3: 鼓 (Drums)                   │ │
│      │  │  ═══════════════════════════════     │ │
│      │  │ 音轨4: 贝斯 (Bass)                  │ │
│      │  │  ═══════════════════════════════     │ │
│      │  │ 音轨5: 用户添加 (可新增无限轨)      │ │
│      │  │  ═══════════════════════════════     │ │
│      │  └─────────────────────────────────────┘ │
│      │                                           │
│      │  [+] 添加音轨    [🎤] 录音    [AI] 生成  │
├──────┴───────────────────────────────────────────┤
│  播放控制（▶️ ⏸️ ⏮️ ⏭️ 🔄 音量 BPM显示）        │
└──────────────────────────────────────────────────┘
```

#### 3.3.2 核心编辑功能

**切割与删减**
- 在时间轴任意位置一键切割（快捷键 B / 或点击切割工具）
- 选中片段后 Delete 删除，后续片段自动前移
- 支持多选、批量删除
- 撤销/重做（无限步数）

**智能桥接（核心亮点）**
- 当用户删减中间一段后，前后两段之间出现空隙
- 用户右键点击空隙 → 选择"AI 桥接"
- 弹出小窗，参数：
  - 桥接时长：自动推荐（默认2-4小节）或手动指定
  - 桥接风格：保持原风格 / 渐变过渡 / 自定义描述
  - 是否保留人声/乐器元素
- Agent 在前后段之间生成一段自然过渡，试听后用户可接受或重新生成
- 桥接难点处理：自动对前后段的 BPM、调性、音色做匹配，确保不突兀

**人声与伴奏分离**
- 选中任意音轨 → "人声分离" → 一键分离为独立的人声轨 + 伴奏轨
- 分离精度对标剪映 AI 分离 + UVR（Ultimate Vocal Remover）
- 分离后可分别编辑、替换、删除

**多音轨编辑**
- 支持无限音轨（实际建议上限 32 轨）
- 每轨独立音量、声像（Pan）、静音（M）、独奏（S）
- 音轨颜色标记、重命名
- 音轨锁定（防止误操作）
- 音轨分组（如把人声所有轨编组）

**片段级 AI 生成**
- 在任意音轨的空白区域，右键 → "在此生成"
- 弹出侧边栏，输入文字描述或上传参考音频
- Agent 在指定位置生成符合上下文的新片段
- 典型场景：在伴奏轨的某一段生成一段 rap、在空白处加一段 solo

**参数调节（每轨/每片段）**
- 音量包络线（可打关键帧做淡入淡出）
- 声像（Pan）
- 音高（Pitch）：-12 ~ +12 半音
- 变速：0.5x ~ 2x（保持音高 / 变调）
- EQ 三频调节（高/中/低）
- 效果器：混响、延迟、压缩（预置一键应用，高级用户可调参数）

**段落标记与导航**
- 在时间轴上自动/手动添加段落标记（Intro, Verse, Chorus 等）
- 点击标记快速跳转
- 段落可拖拽调整位置（连带音频内容移动）

#### 3.3.3 全局混音面板

- 总音量控制
- 限制器（防止爆音）
- 一键母带处理（AI 自动优化响度、动态）
- 导出前响度预览（LUFS 值）

#### 3.3.4 编辑操作的"剪映化"

| 剪映操作习惯 | Lumina 对应实现 |
|-------------|----------------|
| 拖动时间轴预览 | 同样支持，鼠标滚轮缩放 |
| 选中片段 → 分割 | 快捷键 B 或右键菜单 |
| 选中片段 → 删除 | Delete 键，间隙自动闭合 |
| 拖动片段移动 | 拖拽移动，自动吸附对齐 |
| 淡入淡出 | 拖动片段边缘的淡入淡出手柄 |
| 音量调节 | 拖动片段上的音量线 |
| 撤销 | Ctrl/Cmd + Z |

### 3.4 DJ 模式

从编辑工作室一键切换进入 DJ 模式。DJ 模式是一个独立的功能模块，设计语言参考专业 DJ 软件（如 djay Pro AI、Serato），但操作简化到普通用户也能上手。

#### 3.4.1 界面布局

```
┌──────────────────────────────────────────────────┐
│  [编辑室] [DJ模式] [导出]           BPM: 128.0  │
├────────────┬─────────────────┬──────────────────┤
│  曲库/素材  │   Deck A        │   Deck B         │
│  (左侧栏)  │   ┌─────────┐   │   ┌─────────┐    │
│            │   │ 波形图   │   │   │ 波形图   │    │
│  · 当前项目 │   │         │   │   │         │    │
│  · 历史作品 │   │ BPM 128 │   │   │ BPM 128 │    │
│  · 采样库  │   │ Key: Em │   │   │ Key: Em │    │
│  · 效果库  │   └─────────┘   │   └─────────┘    │
│            │   ▶️ ⏸️ CUE     │   ▶️ ⏸️ CUE     │
├────────────┴─────────────────┴──────────────────┤
│  ┌─────────────────────────────────────────────┐│
│  │        Crossfader (横推子)                  ││
│  │   Deck A ◄═══════════════► Deck B          ││
│  └─────────────────────────────────────────────┘│
│  EQ: [Low] [Mid] [High]    FX: [Echo][Rev][Fl] │
│  BPM 同步 🔗   音调锁定 🔒   Loop: [1][2][4][8]│
└──────────────────────────────────────────────────┘
```

#### 3.4.2 DJ 核心功能

**双 Deck 系统**
- Deck A / Deck B 各加载一首歌或片段
- 每 Deck 独立播放/暂停、CUE 点设置、Loop 循环
- 波形图实时显示，颜色区分人声/鼓/和声（基于 AI 分离）
- BPM、Key 自动检测显示

**BPM 控制**
- 手动调节 BPM（滑块/输入）
- BPM 同步：一键将 Deck B 的 BPM 匹配到 Deck A
- 保持音高变速（Master Tempo / Key Lock）
- BPM Tap：手动打拍子检测速度

**DJ 效果器**

| 效果 | 说明 | 参数 |
|------|------|------|
| Echo / Delay | 回声/延迟 | 时间、反馈量、干湿比 |
| Reverb | 混响 | 房间大小、衰减时间、干湿比 |
| Filter | 高低通滤波器 | 截止频率、共振 |
| Flanger | 镶边 | 速率、深度 |
| Phaser | 相位 | 速率、深度 |
| Bit Crusher | 比特压缩 | 位深、降采样率 |
| Beat Repeat | 节拍重复 | 重复长度（1/4, 1/2, 1, 2拍） |
| Roll | 滚奏 | 速度 |
| Brake / Backspin | 刹车/倒转 | 时长 |

效果可叠加，每 Deck 独立效果链。

**循环（Loop）**
- 自动 Loop：1/2/4/8/16 拍循环
- 手动 Loop In/Out 设置
- Loop 区域在波形图上高亮显示
- 支持 Loop 移动（保持循环长度，前后滑动）

**CUE 点**
- 每 Deck 最多 8 个 CUE 点
- 一键跳转到 CUE 点
- CUE 点可通过打击垫快速触发

**横推子（Crossfader）**
- 平滑过渡 Deck A ↔ Deck B
- 曲线可调：线性/渐变/切割

**EQ 三频**
- 每 Deck 独立的 Low / Mid / High EQ
- Kill 开关（一键切掉某频段）

**自动混音（Auto Mix）**
- AI 自动匹配两首歌的 BPM 和 Key
- 自动在合适的位置做过渡（识别歌曲的 Outro/Intro 段落）
- 用户可选择过渡风格：平滑渐进 / 快切 / 效果过渡

#### 3.4.3 DJ 模式与编辑工作室的联动

- DJ 模式中每一轨的音频来源，可以是编辑工作室中的任意音轨或片段
- 在 DJ 模式下做的混音可录制并回传到编辑工作室作为新音轨
- 一键切换：编辑室 ↔ DJ 模式，音频状态保持

#### 3.4.4 采样打击垫（Sampler Pad）

- 8-16 个可自定义的打击垫
- 预置音效库：枪声、掌声、气声、警报、上升音、下降音等 DJ 常用音效
- 用户可上传自定义采样
- 打击垫触发录制到混音中

## 5. 技术选型

### 5.1 客户端技术栈（一期 = macOS 原生）

| 模块 | 技术选型 | 选型理由 |
|------|---------|---------|
| UI 框架 | **SwiftUI + AppKit 混合** | macOS 12+ 原生，性能/视觉/与系统集成 ≫ Electron；AppKit 处理复杂时间轴/拖拽 |
| 音频引擎 | **AVFoundation + AudioKit** | 系统级低延迟回放、AVAudioEngine 节点图；AudioKit 提供 BPM 检测/Loop/效果器 |
| 实时音频处理 | **CoreAudio + Accelerate (vDSP)** | DJ 模式的 scratch / EQ / crossfade 需要 sub-10ms 响应，必须走原生 |
| 波形/频谱可视化 | **Metal + MetalKit** | 多轨长波形 GPU 加速，避免 Canvas 在 60 fps 下卡顿 |
| 持久化 | **SwiftData / Core Data** + 文件系统 | 项目本地优先，云端同步走 S3 兼容 |
| 网络/Agent 协议 | **URLSession + Combine + SSE** | Agent 流式响应；Music 2.6 长任务走 WebSocket/SSE |
| 图标系统 | **SF Symbols 5.0 + 自定义 .symbol 资源** | 系统级 icon，自动跟随 dark mode / dynamic type；emoji 不进生产构建 |
| 字体 | **SF Pro + PingFang SC** | 系统字体，避免 Inter/Roboto 在 macOS 上字距偏移 |
| 打包 / 签发 | **Xcode + Notarization + Sparkle 2** | Apple Developer ID 签名 + 公证；Sparkle 做增量更新 |

**为什么不是 Electron / Web**：
- Electron 启动 1.5–3s、空载 200MB+ 内存，专业音频用户极度反感
- Web Audio API 不支持 sample-accurate scheduling，DJ 模式 BPM Sync / Cue 做不到 ±1ms
- 文件系统访问受限（沙盒），用户拖入 4GB 工程文件需要绕 chunk 上传
- 字体/icon 在 Electron 里渲染跟原生差距明显，"高级感"做不出来

**Windows 二期方案**（V1.5 起评估）：
- 优先 **WinUI 3 + WinRT**（与 macOS 视觉对齐）
- 备选 **Tauri 2 + Rust**（如果跨平台音频引擎收敛能力足够）
- 不走 Electron

### 5.2 模型选型矩阵

| 能力 | 首选模型 | 备选 | 选型理由 |
|------|---------|------|---------|
| 音乐生成 | MiniMax Music 2.6 | - | Cover 功能、BPM/调性锁定、Agent 生态、首包 <20s |
| 人声合成 | MiniMax Speech 2.8 HD | Speech 2.6 | 高清音质、情感控制、零样本克隆、40+语言 |
| 歌词生成 | MiniMax M3 | M2.7 | 百万上下文、原生多模态、高质量创意写作 |
| Agent 对话/推理 | MiniMax M3 | M2.7 | 最强 Agent 能力、复杂多步推理 |
| 封面生成 | Seedream 4.0 | Seedream 3.0 / Midjourney | 2K/4K 输出、风格迁移、中文理解好 |
| 音频分析 | 自研 + 开源模型 | Demucs / UVR | 结构分析、风格分类、BPM/Key 检测 |
| 人声分离 | Demucs v4 / UVR | 剪映 API | 分轨精度高、开源可控 |

### 9.2 补充建议（PRD 作者注）

以下是你在描述中遗漏、但实际产品应该考虑的点：

1. **撤销/重做全局化**：编辑室和 DJ 模式都要有无限制的撤销/重做。搞创作的人手滑是常态。

2. **生成结果多版本**：每次生成至少出 2-4 个版本。AI 音乐有随机性，只出一个版本用户不满意就没得选。

3. **试听缓存**：生成过的版本不要丢了，用户可以回溯之前生成的版本做对比。

4. **歌词编辑器**：在歌词生成环节，应该有一个简单的歌词编辑器——不是只能看，要能改。用户可以手动调整某一句，然后只重新生成那一句对应的旋律。

5. **BPM / Key 手动锁定**：分析出来的 BPM、Key 如果不对，用户要能手改。别让用户被 AI 判断绑死。

6. **快捷键体系**：编辑室对标剪映的操作习惯，空格键播放/暂停、B 切割、Delete 删除、Ctrl+Z 撤销。这是编辑效率的生命线。

7. **暗色模式**：音乐制作软件必须暗色界面，这是行业惯例（保护眼睛、减少视觉干扰）。

8. **进度反馈**：AI 生成/分析/分离的等待时间要有真实的进度条或预估时间，不要干等。Music 2.6 首包延迟 20 秒已经很快了，但用户需要感知到"在动了"。

9. **离线/本地处理选项**：对于有隐私顾虑的用户，部分功能（如人声分离）可考虑本地运算。

10. **DJ 模式键盘映射**：DJ 玩家习惯用键盘快捷键触发 CUE、Loop、效果——给一套默认键盘映射会极大提升专业用户体验。

11. **你的"声音 copy 审核放行"策略是正确的产品决策**，但要考虑：如果用户用 Lumina 克隆了某知名歌手的音色并发布商用作品，法律风险在用户侧。建议在音色克隆功能首次使用时，弹一个确认框让用户勾选："我确认我有权使用此声音样本，并自行承担相关法律责任"——既不影响体验，又保护平台。

**核心操作交互**：

| 操作 | 交互方式 | 视觉反馈 |
|------|---------|---------|
| 切割 | 选中音轨 → 按 `B` 或工具栏 ⟨B⟩ → 点击时间轴位置 | 切割线 `accent/primary` 1px 高亮 100ms 闪烁，片段一分为二 |

| 移动片段 | 拖拽 | 自动吸附到前后片段边缘/拍点（吸附时显示 1px 引导线） |
| 淡入淡出 | 拖动片段边缘的三角形手柄 | 手柄变 `accent/primary`，显示淡入/淡出时长 |
| 音量调节 | 拖动音轨上的音量包络线 | 实时显示 dB 数值（SF Mono） |
| 缩放时间轴 | `⌘` + 滚轮 / 双指捏合 | 标尺刻度变化，无动画 |
| 撤销 | `⌘ Z` | 即时回退 |
| 人声分离 | 右键音轨 → "分离人声/伴奏" | 模态确定型进度条 + 分离后自动生成新轨 |
| AI 桥接 | 右键两段之间的空隙 → "AI 桥接" | 右侧 380px 面板滑入（参数窗） |
| 片段生成 | 右键空白区域 → "在此生成" | 右侧 380px 面板滑入（输入窗） |

**DJ 模式交互规则**：
- 素材库在左侧，可拖拽曲目/片段到 Deck A 或 Deck B
- 波形图支持 Scratch（鼠标在波形上拖动模拟搓碟）
- 效果器按钮为 Toggle 开关，点亮即激活，参数通过旋钮（拖拽调节）
- Crossfader 横推子：鼠标拖动或触控板滑动
- Loop 按钮：点击即激活对应长度的循环，再次点击取消
- BPM Sync：一键将 Deck B 的 BPM 匹配到 Deck A
- 录制按钮：点击开始录制 DJ 混音，再次点击结束并保存到编辑工作室
- 键盘映射（DJ 默认）：
  - `1-8`：Deck A CUE 点触发
  - `Q/W/E`：Deck A Low/Mid/High EQ Kill
  - `A/S/D`：Deck B Low/Mid/High EQ Kill
  - `F/G/H`：Deck A Echo/Reverb/Filter Toggle
  - `Z/X/C`：Deck B Echo/Reverb/Filter Toggle

### 13.2 补充建议（PRD 作者注）

以下是你在描述中遗漏、但实际产品应该考虑的点：

1. **撤销/重做全局化**：编辑室和 DJ 模式都要有无限制的撤销/重做。搞创作的人手滑是常态。

2. **生成结果多版本**：每次生成至少出 2-4 个版本。AI 音乐有随机性，只出一个版本用户不满意就没得选。

3. **试听缓存**：生成过的版本不要丢了，用户可以回溯之前生成的版本做对比。

4. **歌词编辑器**：在歌词生成环节，应该有一个简单的歌词编辑器——不是只能看，要能改。用户可以手动调整某一句，然后只重新生成那一句对应的旋律。

5. **BPM / Key 手动锁定**：分析出来的 BPM、Key 如果不对，用户要能手改。别让用户被 AI 判断绑死。

6. **快捷键体系**：编辑室对标剪映的操作习惯，空格键播放/暂停、B 切割、Delete 删除、Ctrl+Z 撤销。这是编辑效率的生命线。

7. **暗色模式**：音乐制作软件必须暗色界面，这是行业惯例（保护眼睛、减少视觉干扰）。

8. **进度反馈**：AI 生成/分析/分离的等待时间要有真实的进度条或预估时间，不要干等。Music 2.6 首包延迟 20 秒已经很快了，但用户需要感知到"在动了"。

9. **离线/本地处理选项**：对于有隐私顾虑的用户，部分功能（如人声分离）可考虑本地运算。

10. **DJ 模式键盘映射**：DJ 玩家习惯用键盘快捷键触发 CUE、Loop、效果——给一套默认键盘映射会极大提升专业用户体验。

11. **你的"声音 copy 审核放行"策略是正确的产品决策**，但要考虑：如果用户用 Lumina 克隆了某知名歌手的音色并发布商用作品，法律风险在用户侧。建议在音色克隆功能首次使用时，弹一个确认框让用户勾选："我确认我有权使用此声音样本，并自行承担相关法律责任"——既不影响体验，又保护平台。

## 14. v3 变更日志（vs v2.0）

**关键路径上 4 处改动**：

### 14.1 产品形态：Web/Electron → macOS 原生桌面

| 位置 | v2.0 | v3.0 |
|------|------|------|
| §2.1 架构图前端层 | `Web App / Desktop App (Electron)` | `macOS 原生桌面 App (SwiftUI + AppKit)` + Windows 二期独立栈 |
| §6.3 兼容性 | Web + macOS/Windows Electron 封装 | macOS 原生为一期主战场；Web 仅做账号控制台 |

理由：Electron/Web 在专业音频场景下 BPM Sync 做不到 ±1ms、启动慢、内存胖、字体/icon 渲染达不到"高级感"。专业音乐用户 90% 在 macOS。

### 14.2 技术栈：新增 §5.1 客户端技术栈

明确列出 SwiftUI + AppKit + AVFoundation + AudioKit + CoreAudio + Metal + SF Symbols + SF Pro + Sparkle 全套，含选型理由与"为什么不是 Electron"的反驳。

### 14.3 视觉语言：新增 §9.0 设计系统（核心交付）

7 个子小节覆盖配色 / 字体 / **图标系统（含 emoji→SF Symbols 完整映射表，~50 项）** / 间距 / 动效 / 暗色 / 反例。
